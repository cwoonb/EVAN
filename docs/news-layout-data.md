# 뉴스 홈 중요도와 날짜 표시 계약

`lib/news-layout.ts`는 이미 생성된 공개 `NewsIssue` 배열만 사용하는 순수 함수 모음입니다. 뉴스 수집기, LAYA, Qwen, 원본 CSV, 공개 JSON 생성기와 서버 데이터는 변경하지 않습니다. 카드의 크기나 배열 위치가 원래 중요도를 바꾸지 않습니다.

## 중요도

공개 이슈의 `importance`는 기존 CSV `important_score` 1–5 또는 한글 `important`에서 생성됩니다. 기존 생성기는 같은 사건에 속한 출처 중 가장 높은 중요도를 이슈에 사용합니다. 이 UI 도우미는 그 점수를 다시 계산하지 않습니다.

`normalizeNewsImportance(value)`는 정수 1–5, 해당 숫자의 십진 문자열, 다음 명시적 한글 별칭만 수용합니다.

| 값 | 허용하는 한글 | `importanceLabel` |
| --- | --- | --- |
| 5 | `최고중요`, `최고 중요` | `5 · 최고중요` |
| 4 | `매우중요`, `매우 중요` | `4 · 매우중요` |
| 3 | `중요` | `3 · 중요` |
| 2 | `관심` | `2 · 관심` |
| 1 | `일반` | `1 · 일반` |

문자열 앞뒤 공백과 `3.0`, `04`, `+5` 같은 십진 정수 표기는 허용합니다. 소수 점수, 불리언, 빈 값, 알 수 없는 문구, 0과 6–100 등의 범위 밖 점수는 `null`이며 표시는 `미분류`입니다. 0–100 점수를 임의로 나누어 1–5로 환산하지 않습니다. `중요도 5` 같은 표시 문구나 다른 척도를 추측해서 해석하지 않습니다.

## 날짜

홈의 뉴스 날짜는 `issue.updatedAt`을 `Asia/Seoul`의 달력 날짜로 변환한 값입니다. `updatedAt`은 묶음 안에서 가장 최근에 발행된 기사의 시각이며, 유효하지 않을 때만 `issue.publishedAt`을 사용합니다. `publishedAt`은 묶음의 첫 기사 발행 시각입니다. `feed.generatedAt`은 데이터 파일 갱신 시각이므로 뉴스 날짜 필터에 사용하지 않습니다.

`newsDateKey`는 유효한 ISO 날짜·시각을 `YYYY-MM-DD`로 바꾸고 유효하지 않은 입력에는 빈 문자열을 반환합니다. UTC 15:00부터 한국의 다음 날입니다. 시간대가 생략된 ISO 시각은 기존 CSV 생성기와 동일하게 UTC로 해석합니다. 날짜만 있는 `YYYY-MM-DD`도 수용합니다. `2026-02-30` 같은 잘못된 달력 날짜를 다음 달로 자동 보정하지 않습니다. 지역마다 해석이 달라지는 `10/21/2026` 같은 입력은 받지 않습니다.

`filterBriefingIssues`의 `date`는 유효한 `YYYY-MM-DD`만 받습니다. 명시한 날짜가 잘못되었으면 결과가 없으며 전체 날짜로 바꾸지 않습니다. 날짜를 지정하지 않거나 빈 문자열로 전달하면 날짜를 제한하지 않습니다.

## 필터와 그룹

```ts
const filtered = filterBriefingIssues(issues, {
  date: "2026-10-21",
  query: "OpenAI reasoning",
  keyword: "GPT-5.2",
  sort: "latest",
  grade: 4,
});
const groups = groupNewsByImportance(filtered);
```

전체 입력을 먼저 필터링하고 정렬한 뒤 그룹을 나눕니다. `grade`는 최소 중요도가 아닌 정확한 한 등급입니다. `null` 또는 생략은 전체 등급이고, 잘못된 명시 등급은 결과가 없습니다. 1·2등급도 조회할 수 있습니다.

검색 범위는 기존 `filterIssues`와 같습니다. 이슈 제목·요약·카테고리·이벤트 종류, `keywords`, `searchKeywords`, `newTechnologies`, 구조화된 사건 필드, 실제 출처 제목·언론사와 저장된 한국어 표시 제목(`source.display.titleKo`)입니다. 한국어 제목이 있더라도 원문 제목 검색을 유지합니다. 공백으로 나눈 검색어가 모두 포함되어야 합니다. 키워드 필터는 세 태그 배열 중 하나와 대소문자를 무시하고 정확히 일치해야 합니다. 부분 키워드나 기사 본문으로 범위를 확장하지 않습니다.

`latest`는 유효한 `updatedAt`, 없으면 `publishedAt`의 내림차순입니다. `importance`는 등급 내림차순 후 같은 날짜 정렬을 사용합니다. 시각까지 같으면 이슈 ID의 고정 문자열 순서입니다. 시각을 알 수 없는 기사는 마지막에 표시합니다.

그룹은 `groups[5]`, `groups[4]`, `groups[3]`, `groups[2]`, `groups[1]`, `groups.unclassified`입니다. UI에서 등급 순서를 명시적으로 사용합니다. 각 그룹은 정렬된 입력 순서를 보존합니다. 선택 날짜에 5등급이 없으면 4·3등급이나 다른 날짜의 기사를 가져와 채우지 않습니다. 5등급이 여러 개여도 모두 보존하며 6개 카드 제한이나 페이지 분할을 하지 않습니다. 표시 개수 제한이 필요하다면 별도 UI 기능으로 명확히 적용해야 합니다.

같은 `issue.id`만 중복 제거하며 먼저 받은 이슈를 보존합니다. 빈 ID는 사건 동일성을 증명하지 못하므로 합치지 않습니다. 같은 제목·회사·키워드이거나 출처 ID를 공유해도 다른 이슈 ID면 별개 사건으로 남습니다. 이 함수는 사건을 새로 클러스터링하지 않습니다.

입력 배열, 이슈 객체, 출처 배열을 변경하지 않습니다. 반환 배열은 새 배열이며 이슈 객체의 원래 참조를 유지합니다. 따라서 출처 ID, 기존 사건 ID, 관련 기사 연결과 추가 필드가 사라지지 않습니다.

## 목록 링크

```ts
briefingHref({
  grade: 4,
  date: "2026-10-21",
  query: "OpenAI agent",
  keyword: "MCP",
  sort: "importance",
});
// /news?grade=4&date=2026-10-21&q=OpenAI+agent&keyword=MCP&sort=importance
```

기본 정렬 `latest`와 빈 필터는 URL에서 생략합니다. 유효하지 않은 등급·날짜도 링크에는 추가하지 않습니다. `URLSearchParams`로 입력을 인코딩합니다. `/EVAN/`은 기존 Next 기본 경로가 적용하므로 이 함수가 중복해서 붙이지 않습니다. 카드 상세 링크에 실제 `issue`·`article` 식별자를 추가하는 책임은 UI에 있습니다.

## 검증

```sh
node --test tests/news-layout.test.mjs
```

등급과 문자열·알 수 없는 값, 잘못된 0–100 척도, 한국 날짜 경계와 윤년, 최신 시각·대체 날짜·고정 정렬, 날짜·검색·키워드·정확한 등급 필터, 다수의 5등급 유지, 동일 제목의 다른 사건, 입력 불변성과 출처·관련 ID 보존, 링크 인코딩을 검증합니다.
