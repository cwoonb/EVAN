# 뉴스 이미지 운영

뉴스 이미지는 실제 사용 권한이 확인된 기사 이미지, 카테고리 기본 이미지, 공통 이미지, CSS 배경 순서로 표시합니다. 뉴스 수집기·분석 프롬프트·CSV·중요도 분류를 변경하지 않습니다. 화면을 열거나 새 기사가 들어올 때 LLM이나 이미지 생성 API를 호출하지 않습니다.

## 최종 자산

`public/images/news-fallbacks/`에는 최종 제작된 WebP **22개**가 있습니다. SVG 임시 자산이 아닙니다. 내장 `image_gen`으로 각 자산을 한 번씩 독립 생성했고, 생성된 PNG는 보존한 채 크기 조정과 WebP 재인코딩만 적용했습니다. 로컬 GPU·vLLM·CLI/API 키·별도 유료 이미지 서비스는 사용하지 않았습니다.

모든 자산은 1200 × 675, 16:9입니다. 전체 용량은 **871,812 bytes**, 개별 용량은 18,468~102,336 bytes입니다. 프롬프트, 원본 PNG 파일명, 인코딩 설정, 정확한 파일 크기는 [`news-image-prompts.json`](news-image-prompts.json), 자산별 출처 기록은 [`../ASSET-SOURCES.md`](../ASSET-SOURCES.md)에 있습니다. 원본 PNG의 개인 로컬 경로와 제작 진행 기록은 공개 저장소에 포함하지 않습니다.

| 원본 category | 매핑 키 | 최종 파일 |
| --- | --- | --- |
| 기술 | technology | technology-01.webp ~ technology-03.webp |
| 제품 | product | product-01.webp ~ product-03.webp |
| 비즈니스 | business | business-01.webp ~ business-03.webp |
| 시장 | market | market-01.webp ~ market-03.webp |
| 정책 | policy | policy-01.webp ~ policy-03.webp |
| 보안 | security | security-01.webp ~ security-03.webp |
| 기타 | other | other-01.webp ~ other-03.webp |
| 공통 | default | default.webp |

이미지는 실제 사건·제품·인물의 사진이 아닌 분류용 시각 자료입니다. 다크 네이비·차콜·스틸 블루의 중앙 구도로 제작했고 문자·로고·인물·식별 가능한 실제 제품은 넣지 않았습니다. 썸네일에는 작은 `분류 이미지` 표시를 붙이고 장식 이미지의 `alt`는 비워 기사 제목을 중복해서 읽지 않게 합니다. 전체 자산을 합친 검수 이미지는 로컬의 `artifacts/news-fallbacks-contact-sheet.jpg`에 있으며 공개 배포에서는 제외합니다.

## 매핑과 안정적인 선택

설정은 [`../lib/news-images.ts`](../lib/news-images.ts)에 모여 있습니다.

- `categoryImageManifest`: 카테고리별 세 파일과 순서입니다.
- `categoryAliases`: 허용하는 별칭을 명시합니다. NFKC 정규화·공백 제거·영문 소문자 변환 후 정확히 비교합니다. 등록하지 않은 값과 빈 값은 `other`로 처리합니다. 프로토타입 키는 매핑으로 사용하지 않습니다.
- `NEWS_IMAGE_MAPPING_VERSION`: 현재 `category-artwork-v1`입니다.
- `resolveNewsImage`: 승인 정책과 실패 목록을 검사해 현재 표시할 이미지를 반환합니다.
- `nextNewsImage`: 실패한 주소를 기록한 뒤 다음 이미지 단계로 이동합니다.

별칭에는 `technology/tech`, `product/products`, `business`, `market/markets`, `policy/regulation`, `security/cybersecurity`, `other/general`이 있습니다. 원본 `category`를 수정하지 않습니다. `event_type`, 키워드, 검색어, 회사 이름으로 카테고리를 추정하지 않습니다.

변형 선택의 식별자는 안정적인 개별 기사 `source.id`, 원문 URL, 정규화한 제목과 발행 시각 순서입니다. 카드 호출부는 이슈 ID보다 `issue.sources[0].id`를 우선 전달합니다. URL에서는 fragment를 제거하고 쿼리 순서를 정리합니다. 제목의 NFKC·공백만 정규화하며 현재 시각·배열 인덱스·`Math.random()`을 사용하지 않습니다.

고정된 매핑 버전과 기사 식별자의 FNV-1a 해시로 세 변형 중 하나를 선택합니다. 같은 기사가 같은 카테고리에 있으면 정렬·필터·검색 화면·새 기사 추가·새로고침 후에도 같은 파일을 선택합니다. 서버와 브라우저도 동일하게 선택합니다. 카테고리 자체가 수정되면 해당 카테고리의 이미지로 바뀌는 것이 정상입니다. 모든 식별 필드가 비어 있는 기사는 동일한 중립 변형을 사용합니다.

기존 기사 이미지가 의도 없이 바뀌지 않도록 파일 배열의 순서를 유지합니다. 같은 파일명으로 그림만 교체하면 변형의 연결은 유지됩니다. 변형 순서나 해시 정책을 의도적으로 바꿀 때는 매핑 버전과 테스트를 함께 변경하고 화면 영향을 검토합니다.

## 실제 기사 이미지의 승인

현재 공개 JSON에는 대표 기사 이미지가 없고 기존 사용 승인 정책도 없습니다. 따라서 `approvedArticleImagePolicy`와 `registeredLocalArticleImages`는 **빈 목록**으로 시작합니다. 데이터에 URL이 들어 있다는 이유만으로 기사 이미지를 사용하지 않습니다. 유형을 알 수 없는 이미지 값과 빈 문자열도 기본 이미지로 처리합니다.

외부 이미지를 추가하려면 이미지별 사용 조건을 확인한 뒤 `approvedArticleImagePolicy`에 정확한 `url`, 사용 근거 `rightsNote`, 승인 시각 `approvedAt`을 등록합니다. 도메인 전체를 일괄 허용하지 않습니다. 주소가 쿼리를 포함해 바뀌면 다시 검토합니다. 등록 여부와 별개로 HTTPS, 공개 호스트, 기본 HTTPS 포트를 검사하고 사용자 정보·로컬/사설 호스트·IP 리터럴·토큰/비밀번호를 포함한 주소를 거부합니다. 이 구문 검사는 DNS 조회나 저작권 확인을 대신하지 않습니다. 등록 전에 게시자가 허용한 공개 이미지 주소인지 운영자가 확인해야 합니다.

로컬 기사 사진은 실제 파일을 `public/images/`에 저장하고 같은 승인 목록과 `registeredLocalArticleImages`에 경로를 등록해야 합니다. 없는 경로를 등록한 채 배포하지 않습니다. 기본 이미지와 로컬 사진을 실제 사건 사진처럼 잘못 표기하지 않도록 파일의 용도를 함께 검토합니다. 기존 사진이나 기사 전체 본문을 새로 수집하지 않습니다.

403 차단을 우회하는 프록시·쿠키 복제·인증 우회는 없습니다. 외부 이미지 요청에는 `referrerPolicy="no-referrer"`를 사용합니다. 비밀키를 포함한 URL을 공개 정책이나 프론트엔드에 넣지 않습니다.

## 로딩 실패와 배포

[`../components/NewsImage.tsx`](../components/NewsImage.tsx)는 `next/image`를 재사용합니다. CSS wrapper는 기존 전역 `.news-image`와 구분되는 `.news-media`이며 기본 16:9 공간을 미리 확보합니다. 호출부는 카드 크기에 맞게 비율을 조정할 수 있습니다. 대표 이미지에만 preload를 적용하고 나머지는 lazy loading을 사용합니다. 이미지는 22개 정적 파일을 재사용하므로 기사 수만큼 별도 원본을 내려받지 않습니다.

이미지의 403·404·네트워크 오류는 같은 방식으로 처리합니다. 실제 기사 이미지 실패 시 선택된 카테고리 이미지로, 카테고리 실패 시 `default.webp`로, 공통 이미지도 실패하면 CSS 배경으로 이동합니다. 다른 카테고리나 다른 변형을 순회하지 않습니다. 마지막 단계에는 이미지 요소가 없어 반복 오류가 생기지 않습니다. 기사 제목·요약·원문 링크·관련 기사와 데이터 건수는 그대로 유지됩니다.

실패한 원본 주소는 브라우저의 공유 Set에 기록합니다. 같은 페이지와 경로 전환 중 다른 카드가 같은 실패 주소를 다시 요청하지 않도록 초기 선택에서도 건너뜁니다. 공유 실패 기록은 현재 문서의 메모리에만 유지됩니다. 브라우저를 완전히 새로고침하면 다시 시도할 수 있지만 안정적인 카테고리 변형 선택은 바뀌지 않습니다.

로컬 자산은 기존 `assetPath()`를 사용합니다. 개발 루트에서는 `/images/news-fallbacks/...`, GitHub Pages에서는 `/EVAN/images/news-fallbacks/...`로 표시합니다. 정적 내보내기에서 `unoptimized`로 제공하므로 별도 이미지 서버나 런타임 최적화 API가 필요하지 않습니다. 실제 기사 이미지의 외부 URL에는 base path를 붙이지 않습니다.

## 검증

Node.js 24 환경에서 저장소 루트의 다음 명령을 실행합니다.

```sh
npm run test:images
```

직접 실행할 때는 `node --test tests/news-images.test.mjs`를 사용합니다. 현재 **15개 테스트**가 다음 항목을 검증합니다.

- 실제 22개 파일의 존재, WebP 형식, 1200 × 675 치수, 개별·전체 용량.
- 빈 값·알 수 없는 유형·미승인 URL, 승인 근거·시각, 로컬 등록 여부, 공개 URL 안전 조건.
- 일곱 카테고리와 명시적 별칭, 미등록 카테고리·프로토타입 키, 회사/이벤트/키워드와의 독립성.
- 403·404·네트워크 실패 후 유한 전환과 중복 요청 방지, 마지막 CSS 단계에서도 기사 데이터 유지.
- 동일 기사·정렬·필터·새 기사 추가·새 모듈 로드의 안정성, 서버/브라우저의 `/EVAN` 경로 일치.
- 장식 이미지 접근성, 공간 확보, 대표 preload·나머지 lazy, 생성 명세와 실제 파일 크기 일치.

이 테스트는 외부 출판사의 실시간 접근 허용이나 이미지 사용 권한을 확인하지 않습니다. 새로운 외부 승인 항목을 추가할 때는 별도로 실제 브라우저 로딩과 사용 조건을 확인합니다. 일반 웹사이트의 lint·타입 검사·프로덕션 빌드와 모바일·데스크톱 검증도 배포 전 수행합니다.
